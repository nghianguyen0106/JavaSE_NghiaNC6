# 2. OpenFeign/WebClient, Timeout, Retry, Circuit Breaker & Bulkhead
## Mục tiêu

Biết gọi service khác theo cách an toàn trong production, thay vì chỉ gọi HTTP “được là xong”.

## Câu chuyện

Order Service gọi Inventory Service để reserve stock:

`POST /orders
  ↓
Order Service
  ↓
Inventory Service
  ↓
Reserve stock`

Sự cố:

`- Inventory Service chậm 5 giây.
- Order Service timeout 30 giây.
- Order Service retry 3 lần ngay lập tức.
- Checkout threads bị giữ.
- Get Order API cũng bị chậm do dùng chung resource.`

---

## Cần học

### 1. OpenFeign và WebClient

Tìm hiểu khi nào dùng:

| Công cụ | Phù hợp khi |
| --- | --- |
| OpenFeign | Service call dạng declarative interface, flow blocking/MVC |
| WebClient | WebFlux/non-blocking flow hoặc cần gọi async/reactive |
| RestClient | Spring MVC/blocking app hiện đại, gọi HTTP đơn giản |

OpenFeign là declarative HTTP client; Spring Cloud OpenFeign có thể tích hợp với Spring Cloud LoadBalancer và Spring Cloud CircuitBreaker. (docs.spring.io)

### 2. Timeout

Phân biệt:

`- Connect timeout: mất bao lâu để kết nối.
- Read/response timeout: mất bao lâu chờ response.
- Overall request timeout: tổng thời gian cho flow.`

Nguyên tắc:

`Timeout không nên quá dài.
Timeout phải nhỏ hơn timeout của caller phía trên.
Timeout phải phù hợp với SLO.`

### 3. Retry

Tìm hiểu:

`- Lỗi nào được retry:
  + network reset;
  + temporary 503;
  + timeout trong một số trường hợp.

- Lỗi nào không retry:
  + 400 validation error;
  + 401/403;
  + business rule violation;
  + payment request không có idempotency key.`

Retry đúng cần có:

`- Exponential backoff.
- Jitter.
- Retry limit.
- Idempotency.`

### 4. Circuit Breaker và Bulkhead

`Circuit Breaker:
- Closed: gọi bình thường.
- Open: fail fast, không gọi dependency đang lỗi.
- Half-open: thử một số request để kiểm tra dependency hồi phục chưa.

Bulkhead:
- Cô lập resource.
- Inventory bị chậm không được làm Payment/Get Order bị ảnh hưởng.`

Khi bật Spring Cloud CircuitBreaker cho OpenFeign, các Feign client có thể được wrap bởi circuit breaker thông qua cấu hình tương ứng. (docs.spring.io)

## Thực hành

Implement flow:

`Order Service
  ↓
Inventory Client
  ↓
Inventory Service`

Yêu cầu:

`- Timeout 1 giây.
- Retry tối đa 2 lần cho lỗi transient.
- Có backoff.
- Có circuit breaker.
- Có bulkhead hoặc concurrency limit.
- Không retry mù quáng payment request.`

Mô phỏng Inventory Service chậm:

`- Response chậm 3 giây.
- Response trả 500.
- Response trả 400.`

Quan sát:

`- Retry count.
- Circuit breaker state.
- Checkout latency.
- Error rate.
- Get Order có bị ảnh hưởng không.`
