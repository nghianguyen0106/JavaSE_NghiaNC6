# 5. Docker Actuator Health Checks Monitoring & Incident Drill
## **Mục tiêu**

Biết đưa service vào môi trường vận hành và quan sát incident bằng metrics, logs, traces.

## **Câu chuyện**

Flash sale bắt đầu lúc 20:00:

`- Checkout success rate giảm từ 99.8% xuống 91%.
- Inventory latency tăng.
- Kafka consumer lag tăng.
- Outbox backlog tăng.
- Một số user báo: “Đã bị trừ tiền nhưng không có order.”`

Hiện tại team chỉ có:

`- CPU.
- Memory.
- Log rời rạc.`

Không có:

`- Trace ID.
- p95/p99.
- Checkout success rate.
- Outbox backlog.
- Consumer lag.
- Circuit breaker dashboard.`

## **Cần học**

### **1. Dockerize Spring Boot Service**

Tìm hiểu:

`- Multi-stage build.
- .dockerignore.
- Non-root user.
- Environment variables.
- Không commit secret.
- JVM memory trong container.
- Graceful shutdown.`

### **2. Spring Boot Actuator**

Tìm hiểu:

`- /actuator/health
- /actuator/metrics
- Liveness probe.
- Readiness probe.
- Custom health indicator.`

Spring Boot Actuator cung cấp health endpoint và, trong môi trường Kubernetes, các probe endpoint riêng cho liveness/readiness. Tài liệu Spring Boot lưu ý liveness không nên phụ thuộc external system vì có thể dẫn đến restart hàng loạt và cascading failure khi dependency ngoài gặp sự cố. (docs.spring.io)

### **3. Observability**

Phân biệt:

| **Thành phần** | **Trả lời câu hỏi** |
| --- | --- |
| Logs | Lỗi chi tiết là gì? |
| Metrics | Xu hướng/biểu đồ/alert có gì bất thường? |
| Traces | Một request đi qua service nào, chậm/lỗi ở đâu? |

Metric kỹ thuật cần có:

`- Request rate.
- HTTP 4xx/5xx rate.
- p50/p95/p99 latency.
- JVM heap/GC pause.
- Thread pool saturation.
- DB connection pool.
- Circuit breaker state.
- Kafka consumer lag.
- DLQ count.
- Outbox unpublished count.`

Metric business cần có:

`- Checkout success rate.
- Payment success nhưng order pending.
- Inventory reservation failure.
- Duplicate payment prevented count.
- Order stuck ở PAYMENT_PROCESSING.`

### **4. Incident Response**

Khi alert checkout success rate giảm:

`1. Xem business dashboard:
   checkout success rate, payment/order mismatch.

2. Xem technical dashboard:
   p95/p99, 5xx, inventory latency, circuit state,
   Kafka lag, outbox backlog.

3. Dùng trace ID:
   Gateway → Order → Inventory → Payment → Event consumer.

4. Mitigation:
   rate limit / disable feature / open circuit / rollback canary
   tùy evidence.

5. Root cause analysis:
   không kết luận từ CPU/memory một mình.`
