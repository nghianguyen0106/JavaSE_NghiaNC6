# 1. API Gateway, Externalized Configuration & Service Communication Foundation
## **Mục tiêu**

Hiểu cách một hệ thống microservices nhận request từ bên ngoài và quản lý cấu hình/service endpoint theo môi trường.

## **Cần học**

### **1. API Gateway**

Tìm hiểu vai trò của Gateway:

`Client
  ↓
API Gateway
  ├── Route đến Order Service
  ├── Route đến Inventory Service
  └── Route đến Payment Service`

Gateway nên xử lý:

`- Routing.
- CORS.
- Authentication token forwarding.
- Request logging.
- Correlation ID.
- Rate limiting.
- Request/response policy chung.`

Gateway **không nên** chứa business logic như:

`- Tính giá đơn hàng.
- Kiểm tra tồn kho.
- Charge payment.
- Quyết định trạng thái order.`

Spring Cloud Gateway cung cấp routing và filter mechanism; có thể kết hợp filter cho circuit breaker, rate limiting và các cross-cutting concerns ở gateway layer. (docs.spring.io)

### **2. Externalized Configuration**

Tìm hiểu vì sao không hard-code:

`- Service URL.
- Timeout.
- API key.
- Database credential.
- Kafka broker address.
- Feature flag.`

Phân loại config:

| **Loại config** | **Ví dụ** | **Có được commit Git không?** |
| --- | --- | --- |
| Application config | timeout, page size, route config | Có thể |
| Environment config | DB host dev/staging/prod | Có thể, tùy chính sách |
| Secret | password, API key, private key | Không |
| Feature flag | enable-new-payment-flow | Có thể nhưng cần quản lý rõ |

Spring Cloud Config hỗ trợ externalized configuration theo mô hình Config Server/Config Client; client có thể import remote config qua `spring.config.import`. (docs.spring.io)

### **3. Service Discovery và Load Balancing**

Tìm hiểu:

`- Vì sao không hard-code http://inventory-service-01:8080.
- Một service có thể có nhiều instances.
- Client-side load balancing là gì.
- Khi nào dùng Eureka/Consul.
- Khi nào Kubernetes Service/DNS đã đủ.`

Spring Cloud LoadBalancer cung cấp abstraction cho client-side load balancing, với các chiến lược như round-robin và random. (docs.spring.io)

## **Thực hành**

Tạo cấu trúc project:

`order-platform/
├── api-gateway/
├── order-service/
├── inventory-service/
├── payment-service/
└── docker-compose.yml`

Gateway cần route được:

`/api/orders/**      → order-service
/api/inventory/**   → inventory-service
/api/payments/**    → payment-service`

Thêm một global filter để:

`- Đọc header X-Correlation-Id.
- Nếu chưa có thì generate ID mới.
- Forward ID đó xuống service phía sau.
- Log method, path, status và correlation ID.`
