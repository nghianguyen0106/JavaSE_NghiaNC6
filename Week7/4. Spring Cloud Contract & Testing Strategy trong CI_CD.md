# 4. Spring Cloud Contract & Testing Strategy trong CI/CD
## Mục tiêu

Biết biến kiến thức contract testing đã học trước đó thành quality gate trong pipeline.

## Câu chuyện

Order Service cần Product Service trả:

`{
  "id": "P-100",
  "name": "Keyboard",
  "price": 120.50,
  "available": true
}`

Product team deploy API mới:

`{
  "id": "P-100",
  "productName": "Keyboard",
  "unitPrice": 120.50
}`

Kết quả:

`- Product Service health check vẫn xanh.
- Product Service unit test vẫn pass.
- Order Service unit test vẫn pass vì mock cũ.
- Checkout lỗi production.`

---

## Cần học

### 1. Spring Cloud Contract

Tìm hiểu:

`- Producer contract.
- Consumer contract.
- Stub.
- Provider verification.
- Contract artifact.
- Contract version.
- HTTP contract.
- Messaging contract.`

Spring Cloud Contract hỗ trợ consumer-driven và producer-driven contract testing cho HTTP và messaging; framework có Stub Runner và build-tool integration để đưa contract verification vào workflow build/CI. (docs.spring.io)

### 2. Breaking Change

Phân loại:

| API change | Breaking? | Lý do |
| --- | --- | --- |
| Thêm optional field | Không thường xuyên là breaking | Consumer cũ có thể bỏ qua |
| Xóa field bắt buộc | Có | Consumer cần field đó |
| Rename `name` → `productName` | Có | Consumer parse field cũ sẽ lỗi |
| Đổi `price` number → string | Có | Thay đổi type |
| Đổi error response | Có thể | Consumer có thể phụ thuộc error contract |

### 3. CI/CD Testing Strategy

Học viên cần biết mỗi test chạy đúng stage:

`Pull Request:
- Unit test.
- Static analysis.
- Contract verification.

Merge main:
- Integration test.
- Component test.
- Container test.

Staging:
- E2E test cho critical flow.
- Load test.
- Security test.
- Resilience smoke test.

Production:
- Smoke test.
- Synthetic check.
- Canary monitoring.`

`- Khi Product Service đổi response thiếu available:
  provider verification phải fail.`
