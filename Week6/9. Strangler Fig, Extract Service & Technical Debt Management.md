# 9. Strangler Fig, Extract Service & Technical Debt Management
### **Cần học gì**

- Legacy assessment.
- Characterization tests.
- Strangler Fig.
- Facade/API gateway routing.
- Extract service.
- Incremental migration.
- Data migration.
- Dual write/CDC.
- Rollback.
- Technical debt inventory.
- Debt prioritization.

Strangler Fig là cách thay thế dần chức năng legacy bằng thành phần mới, cho phép hệ thống cũ và mới cùng tồn tại trong giai đoạn chuyển đổi; approach này cần routing/proxy phù hợp và rollback plan cho từng phần được tách. (docs.aws.amazon.com)

### **Cần hiểu đến mức nào**

Không nên làm:

`“Rewrite toàn bộ monolith sang microservices trong 6 tháng.”`

Nên làm:

`1. Chọn một capability có boundary tương đối rõ.
2. Có test coverage/characterization test.
3. Đặt facade/router trước monolith.
4. Extract capability sang service/module mới.
5. Chuyển traffic dần.
6. So sánh result giữa cũ/mới.
7. Có rollback.
8. Xóa code cũ khi ổn định.`

### **Assignment**

Tạo `09-modernization-plan.md`.

Legacy HR system có:

`- Monolith 8 năm.
- Shared database.
- Payroll module hay thay đổi.
- Reporting query nặng.
- Notification gửi email nằm trong request synchronous.
- Không có test đủ tốt.`

Developer cần đề xuất:

- Capability tách đầu tiên.
- Capability không nên tách đầu tiên.
- Strangler flow.
- Data migration strategy.
- Rollback plan.
- Technical debt register.
- Risk và success metric.
