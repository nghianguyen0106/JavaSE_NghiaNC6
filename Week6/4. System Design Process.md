# 4. System Design Process
### **Cần học gì**

- Functional requirements.
- Non-functional requirements.
- User flow.
- API/data flow.
- Capacity estimation.
- Storage estimation.
- Read/write ratio.
- Component identification.
- Bottleneck identification.
- Failure scenarios.
- Architecture decision record.

### **Cần hiểu đến mức nào**

System design không nên bắt đầu bằng:

> “Dùng Kafka, Redis, Kubernetes, microservices.”
> 

Nên bắt đầu:

`1. Ai dùng hệ thống?
2. User làm hành động gì?
3. Traffic/read-write ratio là gì?
4. Dữ liệu nào critical?
5. Latency SLA là gì?
6. Failure nào không được chấp nhận?
7. Data tăng thế nào?
8. Component nào chịu trách nhiệm gì?
9. Cần cache, queue, replica hay shard ở đâu?
10. Cần quan sát metric nào?`

### **Assignment**

Tạo `04-system-design-process.md` cho requirement:

`Payroll SaaS:
- 50,000 tenants.
- 5 triệu employees.
- Cuối tháng có 10,000 payroll runs trong 2 giờ.
- Một payroll run có thể chứa 100,000 employees.
- Payslip cần xem trong vòng 2 giây.
- Payroll calculation có thể chạy async.
- Không được tạo duplicate payroll run.
- Audit phải giữ tối thiểu 7 năm.`

Cần nộp:

- Functional requirements.
- NFR.
- Capacity estimation sơ bộ.
- Thành phần chính.
- Data flow.
- Failure scenarios.
- Open questions.

### **Hoàn thành khi**

- [ ]  Bắt đầu từ requirement, không bắt đầu từ technology.
- [ ]  Có capacity estimate dù chỉ là rough estimate.
- [ ]  Nêu rõ assumption.
- [ ]  Có failure scenario và observability từ design đầu tiên.
